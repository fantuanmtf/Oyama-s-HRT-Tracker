The Tools `hrt-cold` validator checks the hand-off envelope and container
shapes; it does **not** validate clinical record semantics or apply restore
rules. The website importer remains authoritative for record validation, merge
behavior, and conflicts. The vectors below were derived by reading both
implementations; they are not a cross-language conformance run and no Tools
tests were executed for this document.

**Authority is path-dependent**

- **TOOLS AUTHORITATIVE (hand-off/container)** — the envelope, `.hrtb`
  container, duplicate-key/depth limits, and OpenPGP encrypt/decrypt/inspect
  rules define whether Tools will accept or encrypt a file. A website parser
  being more permissive does not make the input valid for Tools.
- **WEBSITE AUTHORITATIVE (restore semantics)** — once an envelope is accepted,
  the website decides record validation, tombstone bounds, merge, conflict,
  preference, and scalar behavior. Tools accepting a file does not mean the
  website will restore every record.
- **UNRESOLVED** — the two sides disagree on an interface/product decision, or
  no decision exists; do not claim parity until it is decided in a separate
  approved work item.

## Related invariant (no new field)

The bundle has **no source-account identifier** and this work item does not add
one. The website import preview names the current target account and warns that
the format cannot detect a cross-account bundle; the user must confirm the merge
explicitly. Tools remains opaque to account identity. Whether a future schema
should carry an account identifier is **UNRESOLVED** and out of scope here.

## Review-fix notes (website)

- Expired local tombstones no longer block resurrection of an older incoming
  record; the local map is pruned before the merge decision.
- Prototype-named record ids (`__proto__`, `constructor`, `prototype`) are
  rejected explicitly. Tombstone/accept/final maps use null-prototype objects,
  `Map`, or `Object.hasOwn`, so an inherited value is never read as a deletion.
- Export now shares the importer's entry limit, duplicate-id rejection,
  future-stamp bound, and one cross-version ester rule. Invalid records,
  duplicate ids, and dropped tombstone/stamp entries are reported.
- A preferences-only bundle is reported as "settings only" instead of failure.
  A merge with every category blocked reports nothing applied and does not
  claim success.
- Same-bundle record + tombstone contradictions are reported in the preview.
- Case-variant keys and duplicate JSON keys remain parser-level differences; no
  case-insensitive fallback is added.
